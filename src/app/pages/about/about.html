Acerca de

Qué buscamos con este laboratorio

El objetivo era entender cómo se automatiza la construcción y el despliegue de una aplicación web, y qué cambia en la configuración según la estrategia de enrutamiento que use Angular.

Path Location Strategy

En esta app las rutas son convencionales, por ejemplo /about. El problema es que GitHub Pages solo entrega archivos que existen, y esa ruta no corresponde a ningún archivo. Si alguien la abre directamente o recarga la página, Pages responde con un error 404.

Lo resolvimos copiando index.html como 404.html durante el pipeline. Así, cuando Pages no encuentra la ruta, entrega la aplicación y Angular muestra la vista que corresponde. También tuvimos que construir con --base-href, porque la página vive en una subruta del dominio y no en la raíz.

Cómo se publica

Cada push a main activa un workflow de GitHub Actions que instala las dependencias, corre las pruebas, construye la aplicación, genera el 404.html y la despliega en GitHub Pages.
